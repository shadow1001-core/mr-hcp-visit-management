# 已知限制

本文记录后端评审中已确认、但本轮按优先级暂不处理的 P2 问题。这些条目不是当前功能承诺，后续
修复时应各自先增加回归测试，并同步 API 或数据库设计文档。

## KL-001 数据库会话时区未强制为 UTC

`TIMESTAMPTZ` 能正确保存时间点，但当前连接初始化没有执行 `SET TIME ZONE 'UTC'`。若数据库或
连接默认时区改变，API 序列化可能返回非 `Z` 偏移，虽代表同一时间点，却与契约示例不完全一致。

## KL-002 Decimal 响应编码与示例存在表现差异

当前距离、时长和 finding 数值由 Pydantic 以 JSON 字符串返回，以保持十进制定点精度；部分契约
示例把坐标或距离写成 JSON number。后续需统一契约和序列化策略，避免前端类型理解不一致。

## KL-003 查询接口忽略未知参数

请求体已禁止额外字段，但 FastAPI 默认会忽略列表和看板接口的未知 query 参数。拼错筛选字段时
请求仍可能返回 `200`，而不是契约倾向的 `422`。

## KL-004 数据库不能独立保证完整状态机

Service 层能阻止未签退提交报告；直接 ORM 或 SQL 写入仍可能创建报告，使工作流派生为
`REPORTED`，但签退事实为空。这是文档已声明的应用层约束，数据库尚无跨表约束或触发器兜底。

## KL-005 报告产品校验的数据来源不完全一致

Service 使用计划产品校验实际沟通产品，而数据库复合外键要求产品同时存在于 `visit_products`。
正常流程中两者由签到事务保持一致；若历史数据损坏，两层会在不同阶段拒绝请求。

## KL-006 签退和报告缺少真实并发集成测试

签到已有双线程竞争测试；签退和报告目前只覆盖顺序重复与事务回滚，尚未通过独立数据库连接验证
并发请求最多一个状态迁移生效、报告整体替换不会丢失更新。

## KL-007 Migration 回归检查覆盖有限

现有测试验证数据库升级到 Alembic head，但没有在 pytest 内检查 ORM metadata 与 migration 是否
漂移。当前需额外运行 `alembic check`；后续可将其纳入自动化质量门禁。

## KL-008 前端首屏产物体积偏大

当前 Vite 生产构建可以成功，但主 JavaScript chunk 约为 1.85 MB（gzip 后约 602 KB），超过 Vite
默认的 500 KB 提示阈值。主要来源是 Ant Design 与 ECharts 同步进入首屏包；MVP 功能和桌面端
演示不受影响。后续可通过路由懒加载和手工拆分 vendor chunk 优化，不应仅调高告警阈值隐藏问题。
